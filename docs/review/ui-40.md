# UI + design audit R4: issue #40 recipe page as a feature spread

Reviewer R4, read-only. Sources: after-shots `shots/after1/{light,dark}-recipe{,-long}-*.png`, mockup `2-recipe-spread.jpg`, live app
(extra shots in `scratchpad/r4/`: `ticked-2x.png`, `phone-fold.png`, `min.png`, `desc.png`, `evening-ipad.png`, `print-all.png`).

## Verdict
The spread is a faithful, calm build of the mockup: split opener with rising headline, claret numerals, paper-deep panel with
drawn strike, dotted step links, ink timer chips, pull quote, floating pill. Tokens are used correctly, targets are 44-46px,
focus uses the global 2px ring, `prefers-reduced-motion` stops the photo turn (verified: `animation-name: none`), phone has no
horizontal scroll (scrollWidth 390). It is not ready to ship on four counts:
1. **Print is broken** (`print-all.png`): the quantity column collapses to 1.25rem so "2 tbsp" wraps as "2 / tb / sp", and the photo prints as a full-width black block.
2. **Free-text Serves** ("makes about 4 bowls", recipe 76e1d1e9, `desc.png`) is set in 52px display type and fills the band, three lines tall.
3. **Evening theme**: ink-as-fill components invert to cream, so timer chips and the floating bar are the brightest things on the dark page (`dark-recipe-phone.png`, `evening-ipad.png`).
4. **Phone floating bar** wraps its status to 3 lines and overlaps the photo (`phone-fold.png`); long notes (`light-recipe-long-desktop.png`) run together without paragraph spacing.
The orchestrator's five items are all confirmed (UI-3, 4, 5, 6, 7).

## Must

**UI-1 Must: print quantity column collapses.** `components/ui/IngredientPanel.tsx:57,61`. The checkbox span is `print:hidden` but the grid is still `grid-cols-[1.25rem_5.25rem_minmax(0,1fr)]`, so in print the quantity lands in the 1.25rem track and the name in the 5.25rem track (`print-all.png` page 2: "1 / ts / p", "large / onion, / diced").
Fix: on the button add `print:grid-cols-[5.5rem_minmax(0,1fr)]` (and keep `print:hidden` on the box). Also add `print:break-inside-avoid` to the `li` (line 52). Day/evening: nothing; print forces ink on white (verify the `:root[data-theme=evening]` print reset covers `--panel-bg`, `--qty-fg`, `--numeral-fg`, `--bar-*`; print with `rb-edition=evening` was not tested; do it and add the reset in `globals.css` print block if the page prints dark).

**UI-2 Must: print photo is a full-width black block that eats page 1.** `SpreadOpener.tsx:52`, `globals.css` print block. Acceptance says clean ink-on-white.
Fix: on the photo wrapper add `print:aspect-[3/2] print:max-h-[7cm] print:w-[11cm]`; on the `<img>` add `print:[filter:grayscale(1)_contrast(1.05)]`... or simply `print:hidden` on the whole `<Morph>` block (recommended: smallest, saves ink). Also `print:break-after-avoid` on the h1. Same for the 72px spot icon: it prints; keep (small) or `print:hidden`.

**UI-3 Must: "Serves" free text set as a giant numeral.** `page.tsx:62`, `NumeralsBand.tsx:29`. Recipe 76e1d1e9 has servings "makes about 4 bowls": 3 lines at ~52px, the band is 210px tall vs 110px for the others (`desc.png`), and the text pushes baseline of the label.
Fix: in `page.tsx` test `splitIngredient(servings).quantity === servings` (a pure number or range). If it is, pass as now; if not, pass `{label:"Serves", value: <ScaledServings/>, text:true}` and in `NumeralsBand` render a `text` item in `font-display text-[1.5rem] leading-tight` (clamp 1.25rem to 1.5rem) with `line-clamp-3`. Same in light and dark.

**UI-4 Must: floating bar on phone wraps "READY WHEN YOU ARE" onto 3 lines and covers 90px of the viewport.** `FloatingBar.tsx:11-12`, `RecipeBar.tsx:10` (`phone-fold.png`, `dark-recipe-phone.png`: bar is 3 lines, 98px tall at 390px wide).
Fix: status `className="label min-w-0 whitespace-nowrap"`; bar `gap-3 pl-5`; give the status two lengths: `<span className="sm:hidden">{short}</span><span className="hidden sm:inline">{long}</span>` with short = "Ready?" at 0 and "3 checked" at n>0, long = existing strings. Result: one line, 60px tall at 390px. Keep `role="status"` on the `<p>` (single live region; the hidden span is `display:none` so is not read twice).

**UI-5 Must: evening theme inverts ink-filled components to cream glare.** `styles/components.css:97-98` (`--timer-bg/--timer-fg/--bar-bg/--bar-fg` = `ink`/`paper`), evening blocks at ~L110-120. In the evening edition `--color-ink` is umber-50, so timer chips (`evening-ipad.png`, `dark-recipe-phone.png`) and the whole floating bar are cream on a near-black page; the mockup's evening bar is dark.
Fix: add to BOTH evening blocks (keep `tokens.test.ts` parity): `--timer-bg: var(--color-paper-deep); --timer-fg: var(--color-ink); --bar-bg: var(--color-paper-deep); --bar-fg: var(--color-ink); --bar-focus: var(--color-ink);` and give the chip `border border-(--rule-hair)` (TimerChip, `Method.tsx:43`, 1px) so it stands off `paper`. Keep `--bar-action-*` as is (accent fill). Contrast: ink on paper-deep >= 12:1; the tokens test lines for `--timer-fg/--timer-bg`, `--bar-fg/--bar-bg`, `--bar-focus/--bar-bg` already cover it.

## Should

**UI-6 Should: "1/2 cup" shows raw at 1x.** `lib/scale.ts:61-62` (`factor === 1` returns the input unchanged), seen as "1/2 cup" in `light-recipe-desktop.png` ingredients while 2x shows "1 cup". Also "1 1/2" would not become "1½".
Fix: remove `|| factor === 1`'s early return for the display path: in `scaleQuantity` keep `if (!m) return quantity;` and drop `factor === 1` (so 1x runs through `formatNumber`; "2-3" becomes "2–3", "1/2" becomes "½"). Leave `scaleIngredient` (line 73) as is so cook mode text is not rewritten. Add tests: `scaleQuantity("1/2 cup",1)==="½ cup"`, `("1 1/2 lb",1)==="1½ lb"`, `("2",1)==="2"`. Watch `formatNumber` for values like 0.3 ("⅓") or 1.25 ("1¼") written as decimals: acceptable.

**UI-7 Should: Serves "6-8" uses a hyphen, band shows "6-8".** `page.tsx:62` -> `RecipeState.tsx:65`, visible in `light-recipe-long-desktop.png`. `scaleIngredient` returns the text untouched at 1x.
Fix: in `ScaledServings` always run a range normaliser: `text.replace(/(\d)\s*-\s*(\d)/, "$1–$2")` (U+2013), applied at every scale (and add a `lib/scale` test "6-8"→"6–8"). Also set `font-variant-numeric: lining-nums` already present.

**UI-8 Should: "3:20 hr" superscript after a clock-style value.** `lib/recipe.ts` `minuteNumeral`, `NumeralsBand.tsx:23` (`light-recipe-desktop.png`: "3:20" then raised "hr"; "1:35 hr" in the long shot). The mockup shows bare "3:20" under TOTAL.
Fix: `minuteNumeral` returns `unit: undefined` when `m !== 0` (value "3:20"); keep `spoken` ("3 hr 20 min", already supplied). Whole hours keep "3 hr", minutes keep "20 min". Also change the sup to baseline-lifted but not floating: `[vertical-align:0.9em]` to `[vertical-align:0.75em]`, `text-[0.4em]` to `text-[0.36em]` with `tracking-[0.08em] uppercase`? (optional; just the first change is required.)

**UI-9 Should: long notes have no paragraph spacing.** `PullQuote.tsx:14` (`whitespace-pre-line`), `light-recipe-long-desktop.png`: three paragraphs read as one wall; no quotation marks, no hierarchy.
Fix: for `!short`, render `children` split on `/\n+/` as `<p>` each in `flex flex-col gap-3`; blockquote `text-body max-w-measure`; the caption keeps its place. Needs `notes` passed as string (it is), so in `page.tsx:161` pass `short={notes.length <= 140}` too (200 chars at 34px display is 6+ lines on iPad, `light-recipe-ipad.png` quote already 3 lines at 70 chars). Dark: unchanged tokens.

**UI-10 Should: duplicate spot icons in the no-photo opener.** `page.tsx:96,104`, `light-recipe-long-desktop.png`: a 72px bowl icon above the kicker, then the same bowl at 24px inside "SOUP" badge; unknown tags show a bare circle ("BRAISE", "SUNDAY", `phone-fold.png`) which reads as a bug.
Fix: drop `icon={<SpotIcon .../>}` from the kicker `Badge` (line 96) so only the large icon appears (and only without a photo). If the Badge icon is kept elsewhere it is not touched.

**UI-11 Should: two "Start cooking" buttons on screen at once.** `page.tsx:126` plus the floating bar (`phone-fold.png`, `evening-ipad.png`). The mockup opener has no buttons; the bar owns that action.
Fix: make the opener's primary the Edit action: remove the `Start cooking` ButtonLink from `actions`; make `Edit` `variant="secondary"` (as now) and keep `DeleteRecipeButton`. If the owner wants it kept for no-JS or print, add `hidden` below `lg`... simplest is removal; the bar is rendered server-side so it is available without JS.

**UI-12 Should: section kickers in the method sit equidistant between steps.** `page.tsx:144-150`, `light-recipe-desktop.png` ("TO FINISH" is 38px under step 4 and 40px above step 5, so it reads as belonging to neither).
Fix: outer group wrapper `gap-4` -> add `pt-6 border-t border-(--rule-hair)` on groups after the first (via `i > 0` on the `div` at line 144 using a new `MethodSection` ui wrapper, since pages can't style) and keep inner `gap-4`. Minimum: set the group wrapper to `flex flex-col gap-3` and the parent's `gap-6` to `gap-10` between groups so the kicker hugs its steps.

**UI-13 Should: ticked row keeps a full-strength claret quantity.** `IngredientPanel.tsx:67`, `ticked-2x.png`. Checked name dims to `ink-muted` with a strike, but the claret "8 lb" stays bold, so ticked and unticked rows look equally urgent and the claret quantity gets no strike (mockup strikes the whole row).
Fix: add `group-aria-pressed:opacity-60` to the quantity span, and extend the `.strike` into the quantity: wrap quantity in `<span className="strike">`. Contrast: opacity .6 of claret-700 on cream-100 falls below 4.5:1; instead use `group-aria-pressed:text-ink-muted` for the quantity (ink-muted vs panel is in the tokens test at 4.5+). Same in evening.

**UI-14 Should: target row has no highlight when a step link jumps to it.** `IngredientPanel.tsx:52`, `Method.tsx:31`. Tapping "ribs" scrolls to `#ingredient-0` with no cue where it landed (on phone the list is above the step, scrolls away).
Fix: `li:target` rule in `motion.css`: `li:target > button { background: var(--panel-bg); box-shadow: inset 3px 0 0 var(--qty-fg); }` with `transition`; in reduced motion no transition (colour allowed). Needs only the existing tokens (qty-fg is claret 700 / claret 300, tested against panel). Use `scroll-mt-4`, already set; raise to `scroll-mt-24` on phone so the sticky masthead (if any) does not hide it.

**UI-15 Should: opener photo does not meet the thick rule, 40px gap above band.** `SpreadOpener.tsx:52` and `page.tsx:87` (`gap-10`): `light-recipe-desktop.png` photo ends at y=771 and the band starts at 811, the mockup's photo sits on the rule and bleeds off the right edge. It also ends short on tall viewports.
Fix: give the header `pb-0` and a `-mb-10` on the photo wrapper at `lg` (`lg:-mb-10`) so it lands on the rule, or set the article gap to `gap-0` with `mb-10` on the other sections. Right bleed is optional (`lg:-mr-[max(0px,calc((100vw-72rem)/2))]`); skip if it fights the layout.

**UI-22 Nice: typographic apostrophes in long headlines** ("Grandmother's", `light-recipe-long-desktop.png`; notes "It's"). Fix: a tiny `typographic()` helper (`/(\w)'(\w)/g` to U+2019) applied in `SpreadOpener` for `title` words and `PullQuote` children text. Keep the `<title>` unchanged.
