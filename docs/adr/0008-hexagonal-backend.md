# 0008. Hexagonal (ports and adapters) backend

Status: Accepted · Date: 2026-10-24
Updated: 2026-10-24 (#94), with what phases 2 to 7 (#88 to #93) taught. The Consequences section is the part that changed.

## Context
The backend is one crate in which the layers are tangled. SQL lives in route handlers (`routes/recipes.rs` alone has about 33 sqlx calls). Domain types derive `sqlx::FromRow`, `sqlx::Type` and `utoipa::ToSchema`, and `error.rs` converts `sqlx::Error`. Media calls `tokio::fs` directly from the routes. `AppState` holds a concrete `PgPool` and `reqwest::Client`, so nothing can be swapped. This matters because we want a new storage (another database, object storage for photos), new inbound interfaces (CLI, gRPC, jobs) that reuse the same use cases, and language SDKs generated from a stable OpenAPI contract. Today each of those means touching every route.

## Decision
Make `backend/Cargo.toml` a Cargo workspace. The dependency rule is adapters → app → ports → domain, never the reverse. The compiler enforces it, and `cargo tree` checks in the CI backend job back it up. `domain`, `ports` and `app` may not depend on axum, sqlx, reqwest, tokio, utoipa or hyper. `app` also stays free of image, argon2, rand, sha2 and base64. `adapter-http` may not depend on sqlx, reqwest, image, argon2 or the server crate. A second guard allows `reqwest` only in the `http-fetch` and `anthropic` adapters (the server crate may have it only transitively), and keeps those two and the `html` adapter from depending on `app`, the server, another adapter, axum or sqlx.

| Crate | Holds | May depend on |
|---|---|---|
| `domain` | Recipe, User, Image, validation, time rules, `DomainError` | chrono, uuid, thiserror, url; serde only if a domain type ever needs it (none does today) |
| `ports` | Outbound traits: `RecipeRepo`, `UserRepo`, `SessionRepo`, `MediaStore`, `StorageHealth`, `RecipeExtractor`, `PageFetcher`, `Clock`, ... | `domain` and `async-trait` only; `chrono`, `uuid` and `url` come through `domain`'s re-exports |
| `app` | Use-case services (recipes, imports, media, auth, maintenance; export is a stub) | `domain`, `ports` |
| `adapters-*` | Inbound `http` (routes, DTOs, OpenAPI); outbound `postgres`, `fs-media`, `anthropic`, `http-fetch`, `html`, `memory` (in-memory fakes) | layers above plus their own infra crates |
| `server` | `main.rs`: config, wiring, router, background tasks, and the few port implementations not yet extracted (`Argon2Hasher`, `RandomTokens`, `ImageCrateCodec`, the system `Clock`, `TokioSpawner`) | everything |

Errors are split: `DomainError` lives in `domain`. It grew one variant per outcome a service must tell the adapter about (validation, not found, conflict, forbidden, unauthenticated, unsupported media, the import failures, internal); `AppError`, status codes and the error body live in the HTTP adapter, with `From<DomainError>`.

Search is described in domain terms (`SearchQuery { text, tag, sort, limit, offset }` returning a page of summaries) and each `RecipeRepo` adapter decides how. The cases in `backend/tests/search.rs` and `backend/tests/time_rules.rs` were ported to the traits as the storage contract suite (`ports::contract`) every adapter must pass; the HTTP versions stay in `backend/tests/` as B3 tests. A separate `SearchIndex` port (Tantivy, Meilisearch) is deferred until a second storage exists.

Ports are `async-trait` traits so services can hold `Arc<dyn Port>`, and they return `DomainError` (adapters map their own errors into it; no `sqlx::Error` crosses a port). Besides the crates above, `ports` holds a `contract` feature: the storage contract suite (`ports::contract`), which each adapter runs in its own tests. It uses a manual clock, so it never reads the wall clock, and a `Capabilities` struct lets an adapter that cannot support a case (phrase search, boolean operators) say so; the suite then prints what it skipped.

**Transactions.** A recipe save touches recipes, tags and photo links together. Instead of a unit-of-work port, repository methods are coarse-grained and atomic inside the adapter: `RecipeRepo::create` and `update` take the whole `RecipeInput` (tags and image links included), and `UserRepo::set_password_hash` ends the user's other sessions in the same step. A unit-of-work port would put transaction handles in the trait and tie every adapter to a transaction model. The cost is that a use case cannot combine two repository calls atomically; where one needs that, it gets a new coarse method. Changing a password is verify (slow, outside any lock), then set; so `set_password_hash` is a compare-and-set: it takes the hash the caller verified against and fails with `Conflict` if the stored hash changed in between (an admin reset passes none). Two concurrent changes cannot both succeed on a stale check, which is the guarantee the row lock gives today.

The work is done in eight phases (#87 to #94), each keeping `main` green and `docs/openapi.json` unchanged. Phase 1 keeps the existing `recipe-box-api` package at `backend/` as a workspace member, so the binary name and image entrypoint do not change.

## Consequences
- A new storage or inbound interface is a new adapter, not a rewrite of the routes. The media store (#90) and the AI, fetch and HTML-parsing steps of imports (#92) each became one adapter behind a port.
- Services are tested against in-memory adapters (`crates/app/tests/`), and the contract suite stops search and the time rules behaving differently per backend. See [TESTING.md](../TESTING.md).
- **Transactions.** Coarse-grained repository methods were enough. No use case needed two repository calls to be atomic, so no unit-of-work port was added. Compare-and-set on the password hash kept the guarantee of the old row lock (#88, #89). Race-only error arms in the Postgres adapter are the part that is hard to cover in tests (#89).
- **Errors.** Adapters map their own errors into `DomainError` and `From<DomainError> for AppError` maps each variant to the old status, code and message. Constraint violations that used to be 500s are now 400, 404 or 409, in races only (#89). Internal errors keep their source chain through `DomainError::internal`; services cannot log, so they return non-fatal failures and the HTTP and server layers log them (#91, #92).
- **What stayed in the server crate.** Wiring, config, the purge and backfill tasks, and the port implementations that need `argon2`, `rand`, `image` or tokio. They stay there so that `app` and `adapter-http` can keep the guards above. They are not yet extracted.
- **DTOs and domain types.** They were not merged. The domain has no OpenAPI or serde dependency, so the HTTP DTOs keep `ToSchema` and convert with `From` in `adapters/http/src/dto.rs`. This is the standing cost of the split, and it kept `docs/openapi.json` byte-identical (#91).
- **Contract suite.** Cases run on a manual clock, so they use no wall clock and no sleeps. `Capabilities` lets an adapter decline phrase search or boolean operators, and each skip is printed. The memory adapter runs the suite with every capability and also with none (#88). Writing the ports against the suite exposed two gaps in review: concurrent password changes needed compare-and-set, and the duplicate-link lookup needed its own port method (#88). Postgres relevance is `ts_rank` and memory relevance is a word count, so the suite checks ordering rules, not scores. The Postgres run needs `TEST_DATABASE_URL` and prints a skip message without it (#89).
- **Clock-stamped rows.** Adapters stamp `created_at`, `updated_at` and `deleted_at` from the injected clock instead of the database `now()`. With a frozen clock, rows tie, so the HTTP test harness moves the clock by one microsecond before each recipe save after the first (#89).
- **Imports.** Fetching, AI extraction and HTML parsing are ports (`PageFetcher`, `RecipeExtractor`, `PageReader`), and `ImportService` holds every import rule. `safe_fetch` is private to the `http-fetch` adapter, so the SSRF guard cannot be bypassed from other crates (#92). A `TaskSpawner` port keeps tokio out of `app` and lets a dropped request still clean up its photos.
- **SDK and OpenAPI.** The hexagonal split did not change the contract. Completing the OpenAPI metadata (servers, tags, per-operation security, `operationId` lint) was enough for a generated Python client to work against the real API, using the session cookie (#93, [SDK.md](../SDK.md)).
- **Costs seen.** More crates and boilerplate (every new crate must be added to `backend/Dockerfile`'s dependency layer, or the image build fails), DTO conversions, and wiring changes in two test files. The refactor ran as eight phases. No phase changed `docs/openapi.json`; the only response differences are the race-only ones above.
